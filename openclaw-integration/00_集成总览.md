## 二、适配层次总览（核心）

集成改动分 **6 层**，理解这 6 层就理解全部改动。每层目录、目的、是否入 git 一目了然。

| 层 | 名称 | 主目录/文件 | 目的 | 入 git |
|----|------|-------------|------|--------|
| **L1** | 源码/依赖层 | `openclaw-source/` | 提供被嵌入的 runtime 源码；本地基线跑通验证可起 a2a-gateway | ✅ |
| **L2** | 离线打包层 | `scripts/prepare_openclaw_bundle.sh` → `openclaw-bundle-output/` | 把源加工成扁平/仅 arm64/仅生产依赖的离线自包含产物 | 脚本✅ 产物❌ |

## 三、分层改动详解

### L1 · 源码/依赖层 — `openclaw-source/`

| 项 | 说明 |
|----|------|
| 改动性质 | **几乎未为 harmonymac 改动**，只作为产物源被读取 |
| 阶段0 基线工作 | 重建 `node_modules`（拷贝来的断链，pnpm store 路径变了）；验证 a2a-gateway 是 stock 内置插件且 `loaded`；用 `OPENCLAW_*` 环境变量重定向运行目录，避免污染 `~/.openclaw` |
| 自身定制 | a2a-gateway 做成内置默认插件——这是 **openclaw 自己的定制**，非为 harmonymac |
| Node 约束 | `engines >= 22.16.0`（Node 26 会触发只读 signal TypeError，见 L6） |
| 版本控制 | ✅ 已入 git（8322 文件，`ddb88413`），clone 即得 |

### L2 · 离线打包层 — `scripts/prepare_openclaw_bundle.sh`

| 项 | 说明 |
|----|------|
| 目的 | 从 `openclaw-source/` 产出一个干净、扁平、可随包分发的 runtime 子集 |
| 关键手段 | `pnpm install --prod --node-linker=hoisted --ignore-scripts` + `.npmrc` 限定 `supported-architectures=darwin/arm64` |
| 产物 | `openclaw-bundle-output/`（`openclaw.mjs`/`dist`/`node_modules`/`extensions`/`ui`/`packages`），1.2G |
| 为什么 hoisted | pnpm 默认用符号链接共享依赖，**符号链接在 `.app` bundle/签名时会出问题**；扁平化铺平（实测 0 软链、663 顶层包）规避该风险 |
| 为什么仅 arm64/prod | 减体积 + 匹配 App 目标平台；devDependencies（vitest 等）被剔除 |
| 缓存机制 | 产物已存在则跳过昂贵的 install（避免 Xcode 每次构建重跑）；删产物目录强制重建 |

————主要目的是做到扁平化自包含，从依赖本地 pnpm store 和开发环境变成私有node直接起，并且只保留生产依赖，仅arm64平台，只保留目录下必须的部分。

### L3 · 构建打包层 — `scripts/prepare_node_runtime_bundle.sh` + `project.pbxproj`

| 文件 | 改动 | 目的 |
|------|------|------|
| `scripts/prepare_node_runtime_bundle.sh` | **重写**：移除心跳桩拷贝；改为从 `openclaw-bundle-output/` 拷 openclaw 产物 → `NodeRuntime/openclaw/`；拷 `openclaw.template.json` → `NodeRuntime/config/`；Node 版本提取为 `NODE_VERSION="22.16.0"` 变量（切版本只改一处） | 把三件套（私有 Node + openclaw 产物 + 配置模板）组装进 `.app/Contents/Resources/NodeRuntime/` |

### L5 · 配置注入层 — `openclaw.template.json` + `.template_version` 旁路机制

**核心问题**：sandbox 容器（`~/Library/Containers/<bundle-id>/Data/`）内文件**外部进程只读不可写**（macOS 保护，`Operation not permitted`）。改了模板，旧的容器内 `openclaw.json` 外部删不掉 → 配置永不更新。**解法：让有写权限的 App 自己在版本不一致时重生成。**

**`.template_version` 旁路版本机制**（关键设计，含一次重要演进）：

| 版本阶段 | 做法 | 问题/结果 |
|----------|------|-----------|
| v1（`FIX_a2a` 引入） | `configVersion` 写在 `openclaw.json` 顶层 `"configVersion":1` | ❌ openclaw 严格 schema 判 `Unrecognized key` → 配置无效 → 拒绝起 gateway |
| v2+（`2026-08-05` 修正） | 改为**旁路文件** `.template_version`（config 目录下纯文本数字），`openclaw.json` 保持 schema 合法 | ✅ 配置合法，启动正常 |
| **当前** | `configTemplateVersion = 11`（每次改模板 bump） | 见 `NodeRuntimeManager.swift:184` |

**`prepareRuntimeConfig()` 逻辑**：读 `.template_version` 与 `11` 比对 → 不一致或 `openclaw.json` 缺失 → App 自己删旧、按模板重生成、写新版本号。模板缺失时用内嵌 fallback JSON（a2a 端口 18810）兜底。

**`openclaw.template.json` 当前内容要点**：

| 段 | 内容 |
|----|------|
| `gateway` | `mode:local`(免 `--allow-unconfigured`) + `port:18800` + `auth:none` |
| `agents.defaults.model` | `aajax/gpt-5.6-luna` |
| `models.providers.aajax` | `baseUrl/apiKey(${ANTHROPIC_AUTH_TOKEN})/api:openai-completions` + model 定义 |
| `plugins.entries.a2a-gateway` | `enabled` + `server.port:18810` + `agentCard`(name=MutualInfectionMac) + `security.inboundAuth:none` |

### L6 · 运行时修正（两个 FIX）

| FIX | 问题 | 根因 | 改动 | 结果 |
|-----|------|------|------|------|
| **Node22** | `stderr` 反复 `TypeError: Cannot set property signal of #<IncomingMessage> which has only a getter`，18802 browser control 每请求 500 | Node 26 把 `http.IncomingMessage.signal` 改只读 getter，openclaw auth-profiles 中间件对其赋值 | 私有 Node `v26.5.0`→`v22.16.0 LTS`；版本变量化；新增 `record/node-official/v22.16.0/`（SHA256 校验） | TypeError 消失 |
| **a2a 端口分离** | `curl :18800/.well-known/agent-card.json` 返回 404 | a2a-gateway `server.port=18800` 与主 gateway `--port 18800` 冲突，a2a 没真正绑上，agent-card 路由被主 gateway 404 接管 | 模板 a2a `server.port` `18800`→`18810`；引入 `.template_version` 机制（见 L5）应对容器写保护 | agent-card 在 18810 可访问 |

## 五、运行期完整调用链

### 5.1 Swift 代码调用链（启动 → ready → 退出）

```
AppDelegate.applicationDidFinishLaunching  (:42)
  └─ nodeRuntimeManager.startIfNeeded()                    [stateQueue 串行, 状态机 idle→starting→running]
       ├─ resolveLayout()              解析 bundle 内(只读) + bundle 外(可写) 路径 → Layout
       ├─ prepareWritableDirectories() 建 ~/Library/.../NodeRuntime/{config,state,cache,tmp} + Logs
       ├─ prepareRuntimeConfig()       【.template_version 旁路版本机制 v11】
       │                                  版本不符→App 自行删旧 openclaw.json→按模板重生成→写版本号
       ├─ openLogHandles()             打开 runtime.log / stderr.log
       └─ launchProcess()
            ├─ executableURL = NodeRuntime/node/bin/node
            ├─ arguments    = [openclaw.mjs, "gateway","run","--force","--port","18800"]
            ├─ currentDirectoryURL = NodeRuntime/openclaw/
            ├─ env: OPENCLAW_HOME / OPENCLAW_STATE_DIR / OPENCLAW_CONFIG_PATH → App Application Support
            ├─ stdout/stderr → Pipe → consumeOutput → flushBuffer → handleLine
            │      └─ 匹配 "a2a-gateway: HTTP listening" → didObserveReady=true → log "ready 信号已收到"
            ├─ setpgid(pid,pid)          建独立进程组, 便于整组关闭
            └─ terminationHandler        进程退出→状态 stopped→关日志句柄

AppDelegate.applicationWillTerminate (:115) / applicationShouldTerminate (:462)
  └─ nodeRuntimeManager.stop()        [stateQueue.sync, running→stopping→stopped]
       └─ kill(-pgid, SIGTERM) → waitForProcessExit(3s) → 超时 kill(-pgid, SIGKILL)
```

### 5.2 进程链

```
鸿蒙星河互联.app 【进程 1: Swift 宿主, sandboxed】
   │  职责:拉起/管进程、注入 env、读日志判 ready、退出时 kill 整组
   │      (自己不连下面任何端口!)
   │
   └─ node openclaw.mjs gateway run --force --port 18800  【进程 2: node 引擎】
       │  cwd = .app/…/NodeRuntime/openclaw/   env=OPENCLAW_*
       │
       └─ openclaw-gateway worker 【进程 3: 实际运行时, 与进程2同进程组】
           │  在这一个进程内并行监听多个端口 ↓
           │
           ├─ 服务1  主 gateway     ws/http :18800   ← 控制台/canvas/health  (--port 控制)
           ├─ 服务2  a2a-gateway    http   :18810   ← A2A协议/agent-card ⭐ready信号  (插件)
           ├─ 服务3  a2a-gateway    gRPC   :18811   (插件, server.port+1)
           └─ 服务4  browser control       :18802   (内置)
```

  怎么被启动 / 控制: server.port + 1 自动推导
  ────────────────────────────────────────
  实体: browser control :18802
  本质身份: openclaw 内置的浏览器控制服务
  作用: 给 agent 提供浏览器操作能力(FIX_Node22 修复的就是它每请求 500)
  怎么被启动 / 控制: openclaw 内部

> ⚠️ **端口易混点**：`--port 18800`（代码 `gatewayPort`）只控制**主 gateway**；**a2a-gateway HTTP 端口由配置模板 `server.port` 决定（18810）**，两者独立。ready 日志会显示 a2a 实际端口。

## 七、关键决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| Node 分发方式 | 私有 Node 随包分发，不依赖系统 Node | 用户机器无需装 Node；版本可控 |
| openclaw 依赖结构 | `node-linker=hoisted` 扁平 | pnpm 符号链接在 `.app` bundle/签名时会出问题 |
| 平台/依赖范围 | 仅 darwin/arm64 + 仅 prod | 减体积 + 匹配目标平台 |
| Node 版本 | 22.16.0 LTS（非最新 26） | openclaw `engines>=22.16.0`；Node 26 只读 signal 破坏中间件 |
| ready 检测 | 识别 stdout 日志 `a2a-gateway: HTTP listening`（非 HTTP 轮询） | agent-card 端点定制版 404 不可靠；日志是 openclaw 原生稳定输出 |
| 配置更新 | `.template_version` 旁路版本机制 | sandbox 容器外部只读，只能让 App 自己重生成；旁路文件保持 `openclaw.json` schema 合法 |
| a2a 端口 | 18810（与主 18800 错开） | 避免与主 gateway 冲突；留出 gRPC/browser 间隔 |
| 版本变量化 | `NODE_VERSION="22.16.0"` 单点 | 避免散落硬编码漏改 |

## 十、已知问题与后续优化

1. **体积 1.2G（阶段 5 裁剪未做）**：node_modules 含大量 a2a-gateway 不需要的模块（discord/telegram/whatsapp 等 ~40 渠道插件、`@aws-sdk`、`@lancedb`、`koffi` 多平台 prebuilt、`node-llama-cpp`、`pdfjs-dist` 等，详见 `PHASE1` 体积表）。粗估剔除后可压到 ~300–400M。
2. **`NodeRuntimeHost/` 退役残留**：除 `config/openclaw.template.json` 外的 6 个心跳桩文件已无人引用，建议清理（或把模板移到 `MutualInfectionMac/Resources/`，让 NodeRuntimeHost 整体退出）。
3. **旧 `record/node-official/v26.5.0/`（~115M）** 确认 22.16 稳定后可删。
4. **configVersion 覆盖会丢运行时配置**：bump 版本重生成时，用户手填的 a2a `peers`/`tunnel`/`token` 会被清掉。当前无此类配置可接受；后续需把"模板默认"与"用户覆盖"分离。
5. **a2a `storage.tasksDir` 默认 `~/.openclaw/a2a-tasks`**（PHASE0 路径泄漏项）：跑实际 a2a 任务前，建议在 config 显式指向 App 目录，避免写用户 home。
6. **`NODE_RUNTIME_INTEGRATION_CHECKLIST.md` 已过时**：反映 Node runtime 早期视角，与实际 openclaw 集成脱节，可归档或重写。
