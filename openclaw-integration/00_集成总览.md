# openclaw Agent Runtime 集成到 MutualInfectionMac —— 完整架构与改动总览

> 本文档是 openclaw 集成工作的**入口文档**，面向后续协作者。
> 讲清楚三件本质问题：**① 三个原本独立的项目是怎么合并的、彼此什么关系；② 为了把它们接在一起做了哪些适配改动（不区分是哪一次改的）；③ 哪些文件是最终需要的、哪些是中间产物或已退役残留。**
> 配套分阶段记录见同目录 `PHASE0–4*.md`、`FIX_Node22_换Node22.16.md`、`FIX_a2a端口分离.md`。

## 一、背景：三个独立项目的合并

这套集成把**三个来源完全不同的代码树**拼进同一个目录（`/Users/jiahaoli/project/harmonymac`），让其中一个（openclaw）作为后台 agent runtime 被 embedding 进另一个（harmonymac 的 Mac App）。

| 模块 | 原始身份 | 语言/形态 | 在集成中的角色 |
|------|----------|-----------|----------------|
| **`MutualInfectionMac/`** | harmonymac 仓库原有的 macOS 互传 App（AppKit/Swift） | Swift | **宿主 App**，承担几乎所有适配改动 |
| **`openclaw-custom/`** | 原本独立的 openclaw 定制版仓库（多渠道 AI 网关），整个目录被拷进来 | TypeScript / Node.js | **被嵌入的 agent runtime 源码**（"客"） |
| **`NodeRuntimeHost/`** | harmonymac 仓库原有的"最小 Node 宿主"脚手架，本用来验证"App 能否拉起私有 Node" | TypeScript（心跳桩） | **历史脚手架**，代码入口已被 openclaw 取代，仅剩一个配置模板还在用 |

> ⚠️ `openclaw-custom/` 是**纯目录拷贝**（无内嵌 `.git`），且**从未纳入 harmonymac 的 git 跟踪**（`git ls-files openclaw-custom` 为 0，也未被 `.gitignore` 规则显式忽略，只是从未 `git add`）。协作者 clone harmonymac 后**拿不到 openclaw-custom**，需另行获取（见第九节协作注意）。

```

│  MutualInfectionMac.app  （宿主，Swift，sandboxed Mac App）       │
│                                                                  │
│   AppDelegate                                                    │
│     └─ NodeRuntimeManager  ──(Process)──►  私有 node 二进制       │
│           │                                 │                    │
│           │  注入 OPENCLAW_* 环境变量          │  执行              │
│           │  注入 openclaw.json 配置            ▼                    │
│           │                          ┌──────────────────────┐    │
│           │  读模板 ←── NodeRuntimeHost/   │  openclaw runtime     │    │
│           │            config/            │  (来自 openclaw-custom)│    │
│           │            openclaw.template  │   openclaw.mjs gateway │    │
│           │                              │   a2a-gateway 插件     │    │
└───────────┼────────────────────────────── └──────────────────────┘    │
            │                                                          │
            │  NodeRuntimeHost 退化为"配置模板存放处"，心跳桩代码已退役      │
            └──────────────────────────────────────────────────────────┘

数据/构建流向（自左向右，只在打包时发生一次）：
openclaw-custom/  ──(prepare_openclaw_bundle.sh)──► openclaw-bundle-output/  ──(Xcode Build Phase)──► .app/Contents/Resources/NodeRuntime/
```

**一句话关系**：
- `openclaw-custom` 是"被装进去的东西"的**源码来源**；它本身**几乎不为 harmonymac 做任何改动**，只是被当作产物源使用。
- `MutualInfectionMac` 是"装东西的盒子"，**所有适配改动都集中在这里**（Swift 托管 + 构建脚本 + 工程配置）。
- `NodeRuntimeHost` 是"以前用来试盒子的假东西"，**真东西（openclaw）到位后，它的代码入口被取代，只剩一个 `openclaw.template.json` 配置模板还活着**。

## 三、适配的三个层面（核心改动逻辑）

为了把 openclaw 嵌进 App，适配工作分三层。理解这三层就理解了全部改动。

### 层 1：进程托管层（宿主 Swift 侧）—— "谁来拉起 openclaw、怎么管它"

`NodeRuntimeManager.swift` 是核心。它负责：用 `Process` 拉起 bundle 内的私有 `node`，跑 `openclaw.mjs gateway run`，捕获 stdout/stderr，识别 ready 信号，退出时发 SIGTERM 优雅关闭。

- `Layout` 结构：解析 bundle 内路径（私有 node、openclaw 入口、配置模板）和 sandbox 容器外路径（配置/状态/日志）。
- `launchProcess()`：`node openclaw.mjs gateway run --force --port 18800`，并通过 `OPENCLAW_HOME`/`OPENCLAW_STATE_DIR`/`OPENCLAW_CONFIG_PATH` 环境变量把 openclaw 的写入重定向到 App sandbox 容器内（避免污染用户 `~/.openclaw`）。
- `prepareRuntimeConfig()`：**configVersion 版本机制**（见层 3）。
- ready 检测：识别 openclaw 日志 `a2a-gateway: HTTP listening`。

### 层 2：构建打包层（`scripts/`）—— "怎么把 openclaw 和私有 Node 装进 .app"

两个脚本接力，**只在 Xcode 构建时跑**：

1. `prepare_openclaw_bundle.sh`（一次性，手动触发）：从 `openclaw-custom/` 拷出运行所需文件（`openclaw.mjs`/`dist`/`extensions`/`ui`/`packages`），写打包专用 `.npmrc`（`node-linker=hoisted` + 仅 `darwin/arm64`），跑 `pnpm install --prod` 生成扁平 node_modules，组装成 `openclaw-bundle-output/`。**带缓存**：产物已存在则跳过昂贵的 install。
2. `prepare_node_runtime_bundle.sh`（Xcode Build Phase `Prepare Node Runtime Bundle` 每次构建跑）：从 `record/node-official/v22.16.0/` 提取 arm64 `node` 二进制，把 `openclaw-bundle-output/` 拷成 `NodeRuntime/openclaw/`，把 `openclaw.template.json` 拷成 `NodeRuntime/config/`，组装出 `.app/Contents/Resources/NodeRuntime/`。

### 层 3：配置注入层（`NodeRuntimeHost/config/` + 版本机制）—— "openclaw 用什么配置、配置怎么更新"

- `openclaw.template.json`：a2a-gateway 的默认配置（端口 18810、agentCard、security）。运行时 Swift 实例化为容器内的 `openclaw.json`。
- **configVersion 机制**（关键设计）：sandbox 容器内的文件**外部进程只读不可写**（macOS 保护，`Operation not permitted`），所以改模板后旧配置无法外部清除。解法：模板带 `configVersion`，App 启动时比对版本，不一致则**由 App 自己**（有写权限）删旧配置、按新模板重生成。改配置时只需 bump 模板的 `configVersion`。

## 六、完整调用链

### 6.1 构建期数据流（源 → 产物 → bundle）

```
openclaw-custom/ ──(pnpm install 全量)──┐
                                        ▼
scripts/prepare_openclaw_bundle.sh ──► openclaw-bundle-output/   (一次性)
                                        │  openclaw.mjs / dist / node_modules / extensions / ui / packages
                                        │  (hoisted + 仅 arm64 生产依赖)
record/node-official/v22.16.0/ ─────────┐
                                        ▼
Xcode Build (MutualInfectionMac)
  └─ Build Phase "Prepare Node Runtime Bundle"
       └─ scripts/prepare_node_runtime_bundle.sh
            ├─ 解压 v22.16.0 arm64 → node/bin/node
            ├─ cp openclaw-bundle-output/ → NodeRuntime/openclaw/
            └─ cp openclaw.template.json → NodeRuntime/config/
                                        │
                                        ▼
.app/Contents/Resources/NodeRuntime/
   ├─ node/bin/node                 ← 私有 Node 22.16.0（arm64）
   ├─ openclaw/{openclaw.mjs, dist/, node_modules/, extensions/, packages/, ui/}
   └─ config/openclaw.template.json
```

### 6.2 运行期进程链

```
鸿蒙星河互联网.app  (主进程, bundle id com.HarmonyOSInterconnection.app, sandboxed)
  └─ node openclaw.mjs gateway run --force --port 18800   (cwd = NodeRuntime/openclaw)
     └─ openclaw-gateway  (worker 子进程)
        ├─ 主 gateway      ws://127.0.0.1:18800   (控制台 / canvas / /health)
        ├─ a2a-gateway     HTTP 127.0.0.1:18810  (agent-card / A2A 协议)
        ├─ a2a-gateway     gRPC 127.0.0.1:18801
        ├─ browser control 127.0.0.1:18802
        └─ mDNS            UDP 5353
```

### 6.3 Swift 代码调用链

```
AppDelegate.applicationDidFinishLaunching
  └─ nodeRuntimeManager.startIfNeeded()              [stateQueue 串行]
       ├─ resolveLayout()            解析 bundle 内外路径 → Layout
       ├─ prepareWritableDirectories()  建容器内 config/state/cache/tmp/logs
       ├─ prepareRuntimeConfig()      【configVersion 机制】比对模板/容器版本，不一致则 App 自行重生成 openclaw.json
       ├─ openLogHandles()            打开 runtime.log / stderr.log
       └─ launchProcess()
            ├─ executableURL = nodeBinaryURL
            ├─ arguments = [openclaw.mjs, "gateway","run","--force","--port","18800"]
            ├─ env: OPENCLAW_HOME / OPENCLAW_STATE_DIR / OPENCLAW_CONFIG_PATH → 容器内
            ├─ stdout/stderr → Pipe → consumeOutput → flushBuffer → handleLine
            │      └─ 匹配 "a2a-gateway: HTTP listening" → ready
            └─ terminationHandler → 状态 stopped

AppDelegate.applicationWillTerminate / 退出
  └─ nodeRuntimeManager.stop() → Process.terminate() (SIGTERM) → openclaw 优雅退出
```

## 七、执行流程（从零到运行）

1. **一次性准备**（首次或 openclaw 升级时）
   ```bash
   cd openclaw-custom && pnpm install            # 装全依赖
   cd .. && scripts/prepare_openclaw_bundle.sh   # 生成 openclaw-bundle-output/
   ```
2. **Xcode 构建**：`~/Desktop/Xcode.app` → 选 `MutualInfectionMac` → ⌘B
   - Build Phase 自动跑 `prepare_node_runtime_bundle.sh`，组装 Node 22.16 + openclaw 产物进 `.app`
3. **运行**：⌘R → `AppDelegate` 启动 `NodeRuntimeManager` → 拉起私有 node + openclaw gateway
4. **openclaw 自举**：读容器内 `openclaw.json` → 加载 a2a-gateway 插件 → 监听端口

## 十、已知问题与后续优化

1. **`openclaw-bundle-output/node_modules` 当前是 pnpm 虚拟 store（非扁平），1.2G**
   `prepare_openclaw_bundle.sh` **已经写了** `node-linker=hoisted` 配置，但脚本带缓存命中逻辑，当前产物是**旧缓存**（hoisted 配置加入之前生成的）。**删掉 `openclaw-bundle-output/` 重新跑脚本**才会生成扁平结构，体积和符号链接风险都会改善。这是裁剪阶段的首要优化。
