## 二、适配层次总览（核心）

集成改动分 **6 层**，理解这 6 层就理解全部改动。每层目录、目的、是否入 git 一目了然。

| 层 | 名称 | 主目录/文件 | 目的 | 入 git |
|----|------|-------------|------|--------|
| **L1** | 源码/依赖与插件定制层 | `openclaw-source/` | 提供 runtime 源码，并维护 a2a-gateway 的 registry/tunnel、双向消息/文件、动态本地文件白名单等定制 | ✅ |
| **L2** | 离线打包层 | `scripts/prepare_openclaw_bundle.sh` → `openclaw-bundle-output/` | 把源加工成扁平/仅生产依赖的离线自包含产物；首次缺 `dist` 时自动 install + build | 脚本✅ 产物❌ |
| **L3** | 构建打包层 | `project.pbxproj` 两个 Build Phase + `scripts/prepare_node_runtime_bundle.sh` | 先生成 openclaw 中间产物，再把私有 Node + openclaw + 本机配置模板组装进 `.app` | 工程/脚本✅；模板❌（含密钥） |
| **L4** | 进程托管与上下文注入层 | `MutualInfectionMac/Application/NodeRuntimeManager.swift` + `AppDelegate.swift` | 拉起/管理 openclaw，捕获日志、优雅退出，并生成 workspace 身份、工具与授权目录说明 | ✅ |
| **L5** | 配置/权限层 | `NodeRuntimeHost/config/openclaw.template.json` + entitlements + `.template_version` | 注入模型、鉴权、LAN URL、tunnel/registry、文件目录；同步沙盒真实权限与 Agent/a2a 语义白名单 | 模板❌；其余✅ |
| **L6** | 兼容与联调修正层 | Node 22.16、端口分离、`A2A_LOCAL_FILE_ROOTS`、`verify.sh` | 解决 Node26、端口冲突、Mac 本地文件发送白名单与 Mac↔手机双向消息/文件验证 | ✅（当前部分未提交） |

## 三、分层改动详解

### L1 · 源码/依赖层 — `openclaw-source/`

| 项 | 说明 |
|----|------|
| 改动性质 | runtime 主体仍作为嵌入源，但 **a2a-gateway 已有面向跨设备集成的定制改动**：registry/tunnel、gateway methods、agent tools、文件收发，以及 `A2A_LOCAL_FILE_ROOTS` 动态白名单 |
| 阶段0 基线工作 | 重建 `node_modules`（拷贝来的断链，pnpm store 路径变了）；验证 a2a-gateway 是 stock 内置插件且 `loaded`；用 `OPENCLAW_*` 环境变量重定向运行目录，避免污染 `~/.openclaw` |
| 当前 a2a 能力 | 本机注册为 `TargetMac`，发现 `HW-Phone1`；支持 `message/send`、gateway method `a2a.send_local_file` 与 agent tool `a2a_send_local_file`；入站 inline file 解码后落 `fileStorage.tempDir` |
| Node 约束 | `engines >= 22.16.0`（Node 26 会触发只读 signal TypeError，见 L6） |
| 版本控制 | ✅ 源码已入 git；`dist/`、`node_modules/`、`vendor/` 由根 `.gitignore` 排除，构建时生成 |

### L2 · 离线打包层 — `scripts/prepare_openclaw_bundle.sh`

| 项 | 说明 |
|----|------|
| 目的 | 从 `openclaw-source/` 产出一个干净、扁平、可随包分发的 runtime 子集 |
| 关键手段 | 首次缺 `dist/` 时先在源目录执行 `pnpm install --ignore-scripts && pnpm run build`；staging 再执行 `pnpm install --prod --node-linker=hoisted --ignore-scripts` |
| 产物 | `openclaw-bundle-output/`：`openclaw.mjs` / `dist` / `node_modules` / `extensions` / `ui` / `packages`，并额外打包 `docs/reference/templates` 供 workspace bootstrap |
| 平台配置 | 注释仍描述“仅 arm64”，但当前 `.npmrc` 实际列出 `x64` 与 `arm64`、系统仅 darwin；最终 Node bundle 脚本也支持 `arm64` / `x86_64`，应以脚本实现为准 |
| 为什么 hoisted | pnpm 默认用符号链接共享依赖，**符号链接在 `.app` bundle/签名时会出问题**；扁平化铺平规避该风险 |
| 缓存机制 | `openclaw.mjs` + `node_modules/` 已存在则直接跳过；删除 `openclaw-bundle-output/` 强制重建 |

————主要目的是做到扁平化自包含，从依赖本地 pnpm store 和开发环境变成私有node直接起，并且只保留生产依赖，仅arm64平台，只保留目录下必须的部分。

### L3 · 构建打包层 — `scripts/prepare_node_runtime_bundle.sh` + `project.pbxproj`

| 文件 | 改动 | 目的 |
|------|------|------|
| `scripts/prepare_openclaw_bundle.sh` | 负责生成/缓存 `openclaw-bundle-output/`；源 `dist/` 缺失时自动 install + build；打包 workspace bootstrap 模板 | 让全新或清理后的工作区可以由 Xcode 构建链自动恢复中间产物 |
| `scripts/prepare_node_runtime_bundle.sh` | 移除心跳桩拷贝；从 `openclaw-bundle-output/` 拷 openclaw；拷本机 `openclaw.template.json`；Node 版本集中为 `NODE_VERSION="22.16.0"` | 组装私有 Node + openclaw + 配置模板三件套 |
| `project.pbxproj` | 现有 `Prepare Node Runtime Bundle` 前新增 **`Prepare Openclaw Bundle`（`C0D3A003…`）**；前者 ID 为 `C0D3A002…` | 在 Xcode 构建中先保证中间产物存在，再把完整 NodeRuntime 拷进 `.app` |
| `NodeRuntimeHost/dist/index.js` 等 | 心跳桩退役，不再拷贝 | 心跳桩退出 |

Xcode 构建的实际顺序：

```text
Sources
  → Prepare Openclaw Bundle
      /bin/sh scripts/prepare_openclaw_bundle.sh
      输出 openclaw-bundle-output/{openclaw.mjs,package.json,...}
  → Prepare Node Runtime Bundle
      /bin/sh scripts/prepare_node_runtime_bundle.sh
      输出 .app/Contents/Resources/NodeRuntime/{node,openclaw,config}
  → Resources / Copy Files
```

> `openclaw.template.json` 因含 API key 已被 `.gitignore` 排除。新机器即使源码和脚本齐全，仍必须安全配置这一本机模板，否则第二个 Build Phase 会明确报“配置模板缺失”。

### L5 · 配置注入层 — `openclaw.template.json` + `.template_version` 旁路机制

**核心问题**：sandbox 容器（`~/Library/Containers/<bundle-id>/Data/`）内文件**外部进程只读不可写**（macOS 保护，`Operation not permitted`）。改了模板，旧的容器内 `openclaw.json` 外部删不掉 → 配置永不更新。**解法：让有写权限的 App 自己在版本不一致时重生成。**

**`.template_version` 旁路版本机制**（关键设计，含一次重要演进）：

| 版本阶段 | 做法 | 问题/结果 |
|----------|------|-----------|
| v1（`FIX_a2a` 引入） | `configVersion` 写在 `openclaw.json` 顶层 `"configVersion":1` | ❌ openclaw 严格 schema 判 `Unrecognized key` → 配置无效 → 拒绝起 gateway |
| v2+（`2026-08-05` 修正） | 改为**旁路文件** `.template_version`（config 目录下纯文本数字），`openclaw.json` 保持 schema 合法 | ✅ 配置合法，启动正常 |
| 当前 | `configTemplateVersion = 24`，并结合**模板内容指纹**（格式为 `版本号:哈希`） | 见 `NodeRuntimeManager.swift:287,309-320` |

**`prepareRuntimeConfig()` 当前逻辑**：读取 `.template_version` 中的「版本号:内容指纹」并与 bundle 模板计算结果比对 → 不一致或 `openclaw.json` 缺失时，由 App 自己删除旧配置、复制模板、实例化占位符并写入新标记。`materializeConfigPlaceholders()` 会替换 `${OPENCLAW_STATE_DIR}`、`${OPENCLAW_HOME}`、`${A2A_LAN_IP}`，并预创建 `a2a-tasks` 与 `~/Desktop/A2A-Files`。模板缺失时使用内嵌 fallback JSON（a2a 端口 18810）。

**`openclaw.template.json` 当前内容要点**（含 API key，已被 `.gitignore` 忽略，以本机模板为准）：

| 段 | 内容 |
|----|------|
| `gateway` | `mode:local` + `port:18800` + `auth.mode:token`（本机 gateway token） |
| `agents.defaults.model` | 主模型 `volcengine/qwen3.5-plus`；可选 `ark/Doubao-Seed-Code`、`ark/Kimi-K2.5` |
| `models.providers` | `volcengine` 与 `ark`，均使用 `api:openai-completions`；密钥保存在本机模板，不进 git |
| `plugins.entries.a2a-gateway` | `server{host:0.0.0.0,port:18810}`；`agentCard.name=TargetMac`；动态 LAN URL；公网 relay/tunnel 与 registry；bearer 入站鉴权；任务/audit 写入 `OPENCLAW_STATE_DIR`；入站文件落 `~/Desktop/A2A-Files` |
| `tunnel/registry` | relay/registry 为 `124.71.140.180:8000`；本机身份 `TargetMac`；对端 peer `HW-Phone1`；约 15 秒刷新发现 |
| `security` | A2A 使用 bearer token；文件上限与 inline 文件上限均为 50 MiB；agent 响应超时 20 分钟 |

### 5.5 Mac ↔ HarmonyOS 端到端通信链

当前联调对象：Mac `TargetMac` 与 HarmonyOS 手机 `HW-Phone1`。通信分两种路径：

```text
A. 局域网直接 A2A JSON-RPC（verify.sh 的双向文本用例）
Mac → http://<PHONE_IP>:18800/a2a/jsonrpc → HW-Phone1 Agent
手机/测试端 → http://<MAC_IP>:18810/a2a/jsonrpc → TargetMac Agent
请求均携带 Authorization: Bearer <A2A_TOKEN>

B. registry 发现 + tunnel/relay（跨节点文件方法及非同网场景）
TargetMac / HW-Phone1
   ├─ 启动后向 http://124.71.140.180:8000 注册 serviceId / Agent Card
   ├─ 每约 15 秒刷新 peer 列表
   └─ 通过 ws://124.71.140.180:8000 的 tunnel/relay 与 peer 通信
        └─ gateway method: a2a.send_local_file
```

Mac 主 gateway（18800）是本机控制面，CLI 通过 token 调 `a2a.send_local_file`；Mac A2A HTTP（18810）是外部 A2A 入口。手机端 A2A HTTP 当前为 18800。

> relay/registry **不是 Agent Runtime 本体**，它负责设备注册、发现与隧道转发；实际任务仍由两端各自的 a2a-gateway + Agent 执行。

### 5.6 Agent 的世界观（启动后看到什么）

`NodeRuntimeManager` 在 `launchProcess` 前准备（含 `prepareWorkspaceContext`），OpenClaw 起来后 agent 的「世界观」：

| 来源 | 内容 |
|---|---|
| **workspace**（`.openclaw/workspace/`，session 自动加载） | App 每次启动覆盖 `AGENTS.md`（授权目录、Desktop 收件目录及搬运规则）、`MEMORY.md`（TargetMac/HW-Phone1 身份）、`TOOLS.md`（A2A gateway 调用）；其余 `SOUL.md`/`IDENTITY.md`/`USER.md`/`HEARTBEAT.md` 从 bundle 模板 bootstrap；`BOOTSTRAP.md` 被主动删除 |
| **系统提示**（`buildAgentSystemPrompt`） | Tooling / Tool-Call-Style / Safety / Workspace / Sandbox / Memory / 运行时元数据 等 section，再注入 workspace 文件 |
| **运行配置**（`openclaw.json`） | 主模型 `volcengine/qwen3.5-plus`，可选 `ark/Doubao-Seed-Code` / `ark/Kimi-K2.5`；gateway token；A2A bearer token；TargetMac tunnel/registry/fileStorage 配置 |
| **工具**（OpenClaw 内置，默认 profile） | `group:fs` = read/write/edit/apply_patch（已验证）；另有 runtime(exec/bash)/memory/sessions/ui(browser/canvas) 等组，由 `tools.profile` 决定 |
| **系统层边界** | macOS App Sandbox + entitlement：仅授权目录可读写；OpenClaw 自带 sandbox 是 Docker 机制，本机无 Docker → host 运行，真正隔离靠 macOS 沙盒 |

> 关键：agent「知道」授权范围靠 `AGENTS.md` 被注入系统提示；「真的能读写」靠 entitlement 放行。**两层独立，须同步**。
>
> workspace 完整路径：`$OPENCLAW_HOME/.openclaw/workspace`，`OPENCLAW_HOME = ~/Library/Containers/com.HarmonyOSInterconnection.app/Data/Library/Application Support/MutualInfectionMac/NodeRuntime`（注意有 `.openclaw` 层）。`AGENTS.md` 由 `NodeRuntimeManager.prepareWorkspaceContext()` 每次 launch 前覆盖写入。

### 5.7 一次 `message/send` 的全过程

```
局域网客户端或 tunnel peer → POST :18810/a2a/jsonrpc
   Authorization: Bearer <A2A_TOKEN>
   {jsonrpc:"2.0", method:"message/send",
    params:{message:{messageId, role:"user", parts:[{kind:"text", text:"…"}]}}}
   │
   ▼ ① a2a-gateway 插件收请求
      ├ 校验 inboundAuth=bearer
      ├ 解析 message → 创建/复用 task（task-store，按 messageId 去重）
      └ executor 调度 → 绑定 main session
   ▼ ② agent loop（OpenClaw 核心）
      ├ 组装系统提示（workspace 文件 + 工具 schema + 配置）
      ├ 调主模型 volcengine/qwen3.5-plus（openai-completions）
      ├ 模型决策 → 文本或工具调用（read/write/a2a_send_local_file/…）
      ├ 执行工具：
      │       ├ entitlement 放行真实文件系统访问
      │       ├ AGENTS.md 告知 Agent 应操作哪些目录
      │       └ A2A_LOCAL_FILE_ROOTS 放行 send_local_file 的路径校验
      ├ 工具结果回模型 → 多轮工具调用 → 收敛答案
   ▼ ③ 返回 JSON-RPC
      {result:{status:{state:"completed", message:{parts:[{kind:"text", text:"答案"}]}}}}
   │
   ▼ 原路返回调用端
```

task 状态机 / 队列 / 重试由 `extensions/a2a-gateway` 的 `executor.ts` / `task-store.ts` / `queueing-executor.ts` / `peer-retry.ts` 实现。

### 5.8 Agent 能力边界（T8 落地后）

| 维度 | 能 | 不能/注意事项 |
|---|---|---|
| 文件工具 | 在 `~/project/harmonymac/`、`~/Agent_Workspace/`、`~/Desktop/` 内读/写/创建/编辑 | 目录外仍受 App Sandbox 限制；修改授权根须重新编译/签名 |
| A2A 发送本地文件 | `a2a.send_local_file` / `a2a_send_local_file` 可发送上述授权根内的绝对路径 | 还会经过插件 allowedPrefixes 校验；仅改 entitlement 不够，须同步环境白名单 |
| A2A 接收入站文件 | inline base64 文件解码到 `~/Desktop/A2A-Files`，用户可在 Finder 查看；Agent 会报告真实保存路径 | 首次桌面访问可能触发/依赖 macOS“桌面文件夹”TCC 授权；拒绝后可能失败 |
| 设备发现 | 通过 registry 发现 `HW-Phone1`；通过 tunnel/relay 处理跨网链路 | peer 名、共享 bearer token、serviceId/deviceId 必须两端一致 |
| 交互 | 自然语言定位文件、执行文件操作和跨端消息/文件任务 | 远程无人值守流程不能依赖弹 GUI 选择器 |

**权限链必须四处一致**：

1. `MutualInfectionMac.entitlements` / Debug entitlements：系统真实访问权；
2. `NodeRuntimeManager.authorizedWorkDirs`：唯一代码清单；
3. workspace `AGENTS.md`：让 Agent 知道允许范围；
4. `A2A_LOCAL_FILE_ROOTS`：让 a2a 插件允许从这些路径发送文件。

> 当前授权根含 `~/Desktop/`，因此早期“Desktop 即使 entitlement 也必然被拦”的结论已不再准确：Desktop 仍受 TCC 控制，但在 entitlement 配置正确且用户允许桌面访问后可工作。

## 七、关键决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| Node 分发方式 | 私有 Node 随包分发，不依赖系统 Node | 用户机器无需装 Node；版本可控 |
| openclaw 依赖结构 | `node-linker=hoisted` 扁平 | pnpm 符号链接在 `.app` bundle/签名时会出问题 |
| 平台/依赖范围 | macOS darwin + prod；当前 staging 声明 arm64+x64，实际目标主要为 Apple Silicon | 与 `prepare_openclaw_bundle.sh` / `prepare_node_runtime_bundle.sh` 当前实现一致 |
| Node 版本 | 22.16.0 LTS（非最新 26） | openclaw `engines>=22.16.0`；Node 26 只读 signal 破坏中间件 |
| ready 检测 | 识别 stdout 日志 `a2a-gateway: HTTP listening` | 不把 agent-card 的业务正确性和进程 ready 混为一谈 |
| 配置更新 | `.template_version = 24:<模板内容指纹>` | 容器配置只能由 App 自己更新；指纹能覆盖网络地址/模型等模板内容变化 |
| 敏感模板 | `openclaw.template.json` 不入 git | 模型 API key 和 A2A/gateway token 不应进入仓库；需独立安全分发 |
| 本机身份 | `TargetMac` | 与 agentCard、tunnel.deviceId、registry.serviceId、workspace MEMORY 一致 |
| 对端身份 | `HW-Phone1` | registry peer 名与脚本/Agent 工具说明一致 |
| A2A 鉴权 | bearer token；本机控制 gateway 另用 gateway token | 区分“外部 A2A 请求令牌”和“本机 CLI 调 gateway 的令牌” |
| A2A 端口 | Mac 主 gateway 18800 / A2A HTTP 18810；手机 A2A 18800 | 避免 Mac 主 gateway 与插件冲突，并匹配当前手机配置 |
| 文件授权 | entitlement + AGENTS.md + `A2A_LOCAL_FILE_ROOTS` 同步 | 系统权限、Agent 认知、插件路径校验是三个独立层，缺一不可 |
| 入站文件目录 | `~/Desktop/A2A-Files` | 从不可见容器临时目录改为用户可见收件目录；仍需桌面 TCC 权限 |
| 构建顺序 | `Prepare Openclaw Bundle` → `Prepare Node Runtime Bundle` | 构建机不必预先手动准备中间产物（首次仍可能需联网/pnpm） |
| 版本变量化 | `NODE_VERSION="22.16.0"` 单点 | 避免散落硬编码漏改 |

## 十、已知问题与后续优化

1. **包体仍大（阶段 5 裁剪未做）**：全量生产依赖仍包含大量当前 A2A 场景不需要的 provider/channel/native 包。裁剪前应重新统计当前 `openclaw-bundle-output/`，不要直接套用 08-04 的 1.2G 数值。
2. **敏感模板不进 git**：`openclaw.template.json` 含模型 API key 与通信 token，已被 `.gitignore` 排除。当前构建依赖这一本机文件；需要建立安全的样例模板 + Secret 注入方案，避免新机器构建失败或明文密钥长期留在文件中。
3. **Build Phase 1 首次构建可能联网且耗时**：若 `openclaw-source/dist` 与中间产物都不存在，会运行完整 `pnpm install` + build；构建机必须有 pnpm 和网络/依赖缓存。后续可改为预构建 artifact 或显式 bootstrap 步骤。
4. **脚本平台说明不一致**：`prepare_openclaw_bundle.sh` 的注释仍称“仅 arm64”，但实际 `.npmrc` 声明 x64 + arm64，Node bundle 脚本也支持两种架构。需决定是否正式支持 Intel，再统一注释和构建设置。
5. **Desktop 收件目录依赖 TCC**：即使 entitlements 授权了 `/Users/jiahaoli/Desktop/`，首次访问仍可能需要用户允许“桌面文件夹”；拒绝后入站文件落盘会失败。需补充 UI 引导、错误提示或改用容器目录 + Finder 导出策略。
6. **授权目录硬编码个人绝对路径**：`authorizedWorkDirs`、模板 `fileStorage.tempDir`、脚本工作目录都包含 `/Users/jiahaoli`，不可直接移植给其他用户。后续应基于 `FileManager.homeDirectoryForCurrentUser` / 配置生成动态路径。
7. **权限配置需多处同步**：entitlements、`authorizedWorkDirs`、AGENTS.md、`A2A_LOCAL_FILE_ROOTS` 任一漏改都会出现“Agent 认为可用但系统拒绝”或“系统允许但插件拒绝”的不一致。建议加入静态一致性测试。
8. **配置重生成覆盖本地编辑**：模板标记变化会整体替换 `openclaw.json`，用户在生成文件内手改的 peers/tunnel/token 会丢失。后续应拆分模板默认与用户覆盖。
9. **verify.sh 当前是环境绑定的联调脚本**：写死手机/Mac IP、peer、HDC 路径和令牌，只适用于当前实验环境；且手机离线时无法全绿。建议改成环境变量/参数，并把本地集成检查与真机 E2E 分成两个脚本。
10. **`NodeRuntimeHost/` 仍有历史心跳桩残留**：目前只实际使用 `config/openclaw.template.json`；可把模板迁到专用配置目录后归档该宿主。
11. **旧 Node 26 已清理**：当前 `record/node-official/` 仅剩 v22.16.0；旧文档里“待删 v26”已完成，不再是待办。
12. **`NODE_RUNTIME_INTEGRATION_CHECKLIST.md` 已过时**：仍反映早期最小 Node host 视角，可归档或重写为当前双 Build Phase + A2A 方案。
