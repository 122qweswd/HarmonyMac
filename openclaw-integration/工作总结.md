# OpenClaw 集成个人工作总结

> 总结周期：2026-07-30 ～ 2026-08-20
> 项目：HarmonyMac / `MutualInfectionMac`
> 工作目标：将定制版 OpenClaw 作为离线自包含 Agent Runtime 嵌入 macOS App，并完成与 HarmonyOS 手机的 A2A 双向消息、文件与 Agent 文件操作联调。

## 一、工作概述

本阶段的主要工作，是把原本独立运行的 OpenClaw Node.js 系统接入现有 macOS App，使 `MutualInfectionMac` 不依赖用户机器上的 Node/npm，而是随 App 自带私有 Node、OpenClaw 代码和全部运行依赖。App 启动后自动拉起 OpenClaw gateway，将 Mac 注册为 A2A 节点 `TargetMac`，并与 HarmonyOS 手机节点 `HW-Phone1` 完成消息和文件交互。

工作内容不仅包含“把 Node 进程跑起来”，还覆盖了构建链、依赖打包、进程管理、配置更新、模型接入、A2A 端口与鉴权、设备发现、隧道通信、macOS Sandbox 文件权限、Agent workspace 注入、双端联调脚本和文档沉淀。

当前形成的完整链路：

```text
Xcode Build
  → 自动构建 OpenClaw 中间产物
  → 将私有 Node + OpenClaw + 配置打进 .app
  → App 启动 NodeRuntimeManager
  → 私有 Node 22.16 执行 openclaw.mjs gateway run
  → 主 gateway 18800 + A2A gateway 18810
  → TargetMac 注册 registry / 建立 tunnel
  → 发现 HW-Phone1
  → 双向文本与文件
  → Agent 在授权目录执行真实文件操作
```

## 二、完成的主要工作

## 1. 调研并确定集成路线

### 做了什么

- 分析了现有 `MutualInfectionMac`、历史 `NodeRuntimeHost` 心跳桩和 `openclaw-source` 三套代码的关系。
- 对比了“移植 OpenClaw 官方 macOS App”和“复用现有 NodeRuntime 托管框架”两种路线。
- 最终选择：复用 App 内现有 `Process + 私有 Node` 机制，把历史心跳桩入口替换为真实 `openclaw.mjs gateway run`。

### 解决的问题

- 避免引入独立 SwiftUI App、launchd 和系统 Node 依赖。
- 保持现有 AppKit 应用结构和生命周期不变。
- 为离线、自包含和版本可控奠定基础。

## 2. 跑通 OpenClaw 源码基线

### 做了什么

- 配置 pnpm 并重建 `openclaw-source/node_modules`。
- 定位并解决了拷贝项目后 pnpm 符号链接指向原全局 store、导致 `Cannot find package 'chalk'` 的问题。
- 使用 `OPENCLAW_HOME`、`OPENCLAW_STATE_DIR`、`OPENCLAW_CONFIG_PATH` 将运行状态重定向到测试目录。
- 验证 `a2a-gateway` 插件可以加载，gateway 和 A2A JSON-RPC 可以响应。

- A2A task/audit 的默认路径会泄漏到用户 Home。

### 产出

- 定义了 OpenClaw 集成“跑通”的基础判据。
- 为后续端口分离、路径重定向与配置模板设计提供了事实依据。

## 3. 构造离线自包含 OpenClaw 产物

### 做了什么

- 编写并持续完善 `scripts/prepare_openclaw_bundle.sh`。
- 使用 `pnpm install --prod --node-linker=hoisted --ignore-scripts` 构造扁平生产依赖。
- 将 `openclaw.mjs`、`dist`、`node_modules`、`extensions`、`packages`、`ui` 等运行内容打包到 `openclaw-bundle-output/`。
- 增加缓存：产物已存在时跳过昂贵的依赖安装。
- 后续增强脚本，使 `dist/` 缺失时可以自动执行源码 install + build。
- 将 `docs/reference/templates/` 纳入产物，解决 Agent workspace bootstrap 文件缺失问题。
- 对缺失的生产版 `IDENTITY.md` / `USER.md`，从 `.dev.md` 去除 frontmatter 生成。

### 解决的问题

- pnpm 默认符号链接结构不适合直接随 `.app` 分发和签名。
- 新工作区只有源码、没有 `dist` 时无法构建运行产物。
- OpenClaw Agent dispatch 时缺 workspace bootstrap 模板可能初始化失败。

### 产出

- 可由私有 Node 独立运行的 OpenClaw 中间产物。
- 不依赖系统 Node，不依赖原 pnpm store。
- 为 Xcode 自动构建提供固定输入。

## 5. 实现 Swift 侧 OpenClaw 运行时管理

### 做了什么

将 `NodeRuntimeManager.swift` 从最小心跳宿主重构为完整 OpenClaw 宿主：

- 解析 `.app` 内 Node/OpenClaw/配置路径；
- 创建 Application Support、Logs、state、cache、tmp 等可写目录；
- 使用 `Process` 执行：

```text
node openclaw.mjs gateway run --force --port 18800
```

- 注入 `OPENCLAW_HOME`、`OPENCLAW_STATE_DIR`、`OPENCLAW_CONFIG_PATH`；
- 捕获 stdout/stderr 并分别写入日志；
- 识别 `a2a-gateway: HTTP listening` ready 标记；
- 建立独立进程组；
- App 退出时整组 SIGTERM，超时后 SIGKILL；
- 使用 `terminationHandler` 回收进程、pipe 和日志句柄。

### 解决的问题

- App 与 OpenClaw 生命周期脱节、退出后可能残留子进程。
- 运行日志难以定位。
- OpenClaw 默认将状态写入用户 Home。

## 6. 修复 Node 26 兼容性问题

### 问题

使用 Node v26.5.0 时，OpenClaw 中间件反复报错：

```text
TypeError: Cannot set property signal of #<IncomingMessage> which has only a getter
```

并导致 browser control 等请求返回 500。

### 做了什么

- 定位到 Node 26 将 `IncomingMessage.signal` 改为只读，而 OpenClaw 依赖链仍尝试赋值。
- 下载并校验 Node v22.16.0 LTS 的 arm64/x64 官方包。
- 修改打包脚本使用 v22.16.0。
- 验证错误消失。
- 后续清理旧 v26 包，目前 `record/node-official/` 只保留 v22.16.0。

### 结果

- 私有 Node 版本稳定在 OpenClaw `engines >= 22.16.0` 的兼容基线。
- 为后续模型、A2A、文件能力提供稳定运行环境。

## 7. 修复 A2A 端口冲突与配置更新问题

### 问题一：端口冲突

- OpenClaw 主 gateway 使用 18800；
- a2a-gateway 也配置 18800；
- Agent Card 请求实际命中主 gateway 404。

### 解决

- Mac 主 gateway 保持 18800；
- Mac a2a-gateway 改为 18810；
- A2A gRPC 使用后续端口（通常 18811）。

### 问题二：旧沙盒配置无法从终端修改

App Sandbox 容器内 `openclaw.json` 对外部进程写保护。只改 bundle 模板不会覆盖已生成的旧配置。

### 解决演进

1. 初版把 `configVersion` 写入 JSON 顶层；
2. OpenClaw 严格 schema 拒绝未知字段；
3. 改为旁路 `.template_version`；
4. 最新进一步升级为：

```text
24:<模板内容指纹>
```

Swift 对模板计算内容指纹，模型、网络地址或配置内容变化都能触发 App 自行重生成。

### 同时完成

- 替换 `${OPENCLAW_STATE_DIR}`；
- 替换 `${OPENCLAW_HOME}`；
- 动态探测 LAN IPv4 替换 `${A2A_LAN_IP}`；
- 预创建 A2A task 和文件目录。

## 11. 打通 macOS Sandbox 文件访问

### 问题

OpenClaw 作为沙盒 App 子进程，真实文件访问受 App Sandbox 限制。仅在 prompt 中告诉 Agent“可访问”并不能获得系统权限。

### 做了什么

在 Release/Debug entitlements 加入：

- 项目目录读写；
- `~/Agent_Workspace/` 读写；
- `~/Desktop/` 读写；
- network client/server；
- downloads read-write；
- user-selected read-only。

在 Swift 中维护相同的 `authorizedWorkDirs`，并写入 AGENTS.md。

### 进一步发现

A2A 插件的 `send_local_file` 还有自己独立的 `allowedPrefixes`，即使 macOS 已授权，插件仍会拒绝 Mac 路径。

### 最新修复

- `NodeRuntimeManager` 注入：

```text
A2A_LOCAL_FILE_ROOTS=/Users/.../harmonymac/:/Users/.../Agent_Workspace/:/Users/.../Desktop/
```

- `a2a-gateway/index.ts` 读取该变量并并入 `allowedPrefixes`。

### 形成的权限闭环

```text
entitlement                 系统真实权限
authorizedWorkDirs          代码唯一目录清单
AGENTS.md                   Agent 语义认知
A2A_LOCAL_FILE_ROOTS        A2A 文件发送路径校验
```

这项工作解决了“Agent 能读写文件，但 A2A 发送工具仍说路径不允许”的最后一层问题。

## 12. 实现手机→Mac 文件可见落盘

### 原方案

入站文件落在 App 容器内 `state/a2a-files`，用户在 Finder 中不容易查看。

### 最新方案

将 `fileStorage.tempDir` 与 Swift 收件目录统一为：

```text
/Users/jiahaoli/Desktop/A2A-Files
```

并在 App 启动时预创建。

A2A executor 收到 inline base64 文件后：

1. 解码文件；
2. 保留/清洗原始文件名；
3. 写入 Desktop 收件目录；
4. 产生 `【A2A 文件接收成功】` 内部文本；
5. 要求 Agent 向用户原样报告真实保存路径。

### 结果

- 手机发来的文件对用户可见；
- Agent 能按用户指定目的地在授权目录内移动/复制；
- 路径汇报与真实文件系统一致。

### 风险

Desktop 仍受 macOS TCC 控制，首次访问可能需要用户允许“桌面文件夹”。

## 三、解决的关键技术问题

| 问题 | 根因 | 解决方案 |
|---|---|---|
| pnpm 依赖拷贝后断链 | node_modules 指向原全局 store | 重装依赖；分发产物使用 hoisted |
| App 依赖用户 Node | 原运行入口使用外部环境 | 私有 Node 22.16 随 `.app` 分发 |
| Node26 TypeError | IncomingMessage.signal 只读 | 回退 Node 22.16 LTS |
| Agent Card 404 | 主 gateway 与 A2A 共用 18800 | Mac A2A 分离到 18810 |
| 容器旧配置无法手动覆盖 | App Sandbox 容器保护 | App 内 `.template_version` 自愈 |
| 顶层 configVersion schema 错误 | OpenClaw 严格 schema | 使用旁路文件，不污染 JSON |
| 改模板未 bump 版本 | 纯整数版本容易漏改 | 版本号 + 模板内容指纹 |
| 手机无法访问 localhost | Agent Card 固定 127.0.0.1 | Swift 动态探测 LAN IPv4 |
| A2A 无设备发现 | 静态 peer/网络变化 | registry + tunnel/relay |
| Agent 不知道授权目录 | 系统权限与 prompt 独立 | App 生成 AGENTS.md |
| 系统允许但 send_local_file 拒绝 | 插件有独立 allowedPrefixes | `A2A_LOCAL_FILE_ROOTS` 动态注入 |
| 手机入站文件用户不可见 | 落在沙盒容器 | 改到 `~/Desktop/A2A-Files` |
| 模型代理流式异常 | Anthropic SSE 顺序不兼容 | 使用 openai-completions |
| 构建前必须手动准备产物 | Xcode 只有 NodeRuntime Phase | 新增 Prepare Openclaw Bundle |
| 大产物/密钥污染仓库 | 构建物和模板直接跟踪 | `.gitignore` + 可重建脚本 + 敏感模板外置 |

## 四、最终形成的系统能力

### 1. 自包含运行

- 私有 Node v22.16.0；
- OpenClaw 代码与生产依赖随 App；
- 不依赖用户系统 Node/npm；
- 状态、日志与配置进入 App 管理目录。

### 2. Agent 能力

- 模型调用；
- 文件读写/创建/编辑；
- 项目目录、Agent_Workspace、Desktop 授权；
