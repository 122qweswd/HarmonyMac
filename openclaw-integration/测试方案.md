# OpenClaw 集成与 Mac ↔ HarmonyOS A2A 测试方案

> 最后同步：2026-08-20
> 测试对象：`MutualInfectionMac` 内嵌 OpenClaw、Mac `TargetMac` 与 HarmonyOS 手机 `HW-Phone1`
> 架构与实现背景见 [00_集成总览.md](./00_集成总览.md)。

## 1. 测试分层

| 层级 | 目的 | 是否依赖手机 | 是否依赖模型 |
|---|---|---:|---:|
| A. 构建与静态检查 | 脚本、模板、私有 Node、Build Phase 是否齐全 | 否 | 否 |
| B. App Runtime 集成 | App 是否拉起私有 Node/OpenClaw，端口、配置、日志是否正确 | 否 | 否 |
| C. Agent 文件能力 | Agent 是否能在授权目录真实读写 | 否 | 是 |
| D. 双端 A2A 消息 | TargetMac ↔ HW-Phone1 双向 `message/send` | 是 | 是 |
| E. 双端 A2A 文件 | Mac→手机、手机→Mac `send_local_file` 与真实落盘 | 是 | 视对端流程而定 |
| F. 生命周期与回归 | 退出清理、缓存重建、配置变更、错误场景 | 部分 | 部分 |

> `verify.sh` 现在是 **D/E 真机联调脚本**，不再是单纯本地集成检查。手机离线时，应先执行 A/B/C，不应把真机脚本失败误判为 App Runtime 集成失败。

```bash
BODY=$(python3 - <<'PY'
import json, os, uuid
path=os.path.expanduser('~/Agent_Workspace/read-test.txt')
print(json.dumps({
  'jsonrpc':'2.0',
  'id':'file-read',
  'method':'message/send',
  'params':{
    'message':{
      'messageId':str(uuid.uuid4()),
      'role':'user',
      'parts':[{'kind':'text','text':f'读取文件 {path} 的第一行并原样返回。'}]

    'configuration':{}

  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $A2A_TOKEN" \
  --data-binary "$BODY" \
```

# Part E：Mac ↔ HarmonyOS 双向文件（手机在线）

## E1. Mac → 手机

```bash
MAC_FILE="$HOME/Agent_Workspace/mac-to-phone.txt"
printf 'MAC_TO_PHONE_FILE_OK\n' > "$MAC_FILE"

export OPENCLAW_HOME="$BASE"
export OPENCLAW_STATE_DIR="$BASE/state"
export OPENCLAW_CONFIG_PATH="$BASE/config/openclaw.json"

PARAMS=$(printf '{"peer":"HW-Phone1","path":"%s"}' "$MAC_FILE")

"$NODE" "$MJS" gateway call a2a.send_local_file \
  --url=ws://127.0.0.1:18800 \
  --token="$GATEWAY_TOKEN" \
  --timeout=300000 \
  --params="$PARAMS"
```

期望：请求成功/接受；不能出现：

```text
path not in allowed roots
```

若出现，排查：

1. `.app` 是否包含最新 a2a 插件源码；
2. 是否重建 `openclaw-bundle-output/`；
3. `NodeRuntimeManager` 是否注入 `A2A_LOCAL_FILE_ROOTS`；
4. 路径是否在 `authorizedWorkDirs` 内。

手机落盘检查：

```bash
PHONE_RECEIVE_DIR=/storage/media/100/local/files/Docs/OPENCLAW
"$HDC" shell "find '$PHONE_RECEIVE_DIR' -maxdepth 1 -type f | tail -20"
```

最终判据：手机目录出现文件，且内容含 `MAC_TO_PHONE_FILE_OK`。

## E2. 手机 → Mac

当前 fixture：

```text
/data/local/.openclaw/workspace/a2a-fixtures/phone-to-pc-test.txt
```

通过 HDC 执行手机 OpenClaw：

```bash
PHONE_PARAMS='{"peer":"TargetMac","path":"/data/local/.openclaw/workspace/a2a-fixtures/phone-to-pc-test.txt"}'

"$HDC" shell "/data/local/npm/bin/openclaw gateway call a2a.send_local_file \
  --token=<PHONE_GATEWAY_TOKEN> \
  --timeout=300000 \
  --params='$PHONE_PARAMS'"
```

Mac 落盘检查：

```bash
find "$HOME/Desktop/A2A-Files" -maxdepth 1 -type f -print
```

最终判据：

- 文件真实存在于 `~/Desktop/A2A-Files/`；
- 文件名和内容与手机 fixture 一致；
- Agent 回复中的“保存路径”与真实绝对路径一致。

## E3. 文件安全边界

至少验证：

- 相对路径被拒绝；
- NUL 路径被拒绝；
- 未授权根路径被拒绝；
- 大于 `maxFileSizeBytes` 的文件被拒绝；
- 重名文件不会无提示覆盖（按当前 executor 行为记录实际结果）。


- A2A bearer token 错误；
- 本机 gateway token 错误；

## F5. registry / tunnel 故障

- 本地 Mac gateway 和 A2A 是否仍健康；
- 局域网直连文本是否仍可用；
- 跨网 peer 发现/文件是否按预期失败并给出可诊断错误。

# 失败排查速查

| 现象 | 优先原因 | 处理 |
|---|---|---|
| Build Phase 报配置模板缺失 | 模板被 gitignore，新机器未配置 | 从安全配置源恢复 `NodeRuntimeHost/config/openclaw.template.json` |
| Build Phase 报 openclaw 产物缺失 | Phase 1 未执行/失败 | 看 `Prepare Openclaw Bundle` 日志；手动跑脚本 |
| `pnpm` 不存在 | 首次需要构建 dist | 安装 pnpm 或提供预构建中间产物 |
| App 无 OpenClaw | 配置/schema/Node/产物错误 | 看 `runtime.log`、`stderr.log` |
| Mac Agent Card 404 | 请求错到 18800，或 a2a 未起 | 改用 18810，查 ready 日志 |
| Mac Agent Card 401/403 | A2A bearer token 缺失/错误 | 加正确 Authorization header |
| `.template_version` 还是纯数字 | 运行的是旧 App | Clean/Rebuild，确认最新 NodeRuntimeManager |
| `path not in allowed roots` | 未打入 `A2A_LOCAL_FILE_ROOTS` 修改或路径不在授权根 | 强制重建 bundle/App，检查授权目录 |
| Desktop 落盘失败 | TCC 未允许或 entitlements 不一致 | 检查系统隐私授权、Release/Debug entitlement |
| `peer not found` | 手机未注册、registry 未刷新、peer 名错误 | 查 registry、等待刷新、确认 `HW-Phone1` |
| `unauthorized` | gateway token / A2A token 混用 | 区分两个 token |
| HDC `[Empty]` | 手机未连接 | 恢复 HDC 后再跑真机测试 |
| Node signal TypeError | App 仍用 Node26/旧 bundle | 检查私有 Node v22.16.0，重新构建 |
| App 退出后端口仍占用 | 未走正常退出或进程组清理失败 | 用 ⌘Q 复测，查 process group 和日志 |
