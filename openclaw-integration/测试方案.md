# MutualInfectionMac OpenClaw 集成测试方案

## 测试方式

本次采用“用户启动 App，我执行检查”的方式：

- **你负责**：使用完整 Xcode 构建并启动 `MutualInfectionMac`；
- **我负责**：检查进程、端口、日志、私有 Node 版本、配置和接口，并汇报是否通过。

请不要手动启动 OpenClaw，也不要执行 `pkill`；否则会影响进程链和退出清理判断。

---

## 第 1 步：准备并构建 App

### 你执行

1. 确认已安装完整 Xcode，并打开项目：

```bash
cd /Users/jiahaoli/project/harmonymac
open MutualInfection.xcodeproj
```

2. 在 Xcode 顶部选择 scheme：`MutualInfectionMac`；
3. 选择本机 macOS 运行目标；
4. 执行 `Product → Build`，或按 `⌘B`；
5. 确认 Build 成功，并且 Build Log 中的 `Prepare Node Runtime Bundle` 没有报错；
6. 执行 `⌘R` 启动 App；
7. 等待约 10 秒，不要退出 App；
8. 在对话中回复：

```text
App 已启动，请检查
```

### 期望结果

- Xcode Build 成功；
- `Prepare Node Runtime Bundle` 成功；
- App 窗口正常出现；
- App 保持运行，等待我检查。

### 测试内容与作用

验证 Xcode 是否把私有 Node、OpenClaw 和配置模板打入 `.app`，并验证 `AppDelegate` 是否实际启动了 `NodeRuntimeManager`。

---

## 第 2 步：我检查 App 内运行时文件

### 我执行

定位 Xcode 生成的 `.app`，检查：

```text
Contents/Resources/NodeRuntime/node/bin/node
Contents/Resources/NodeRuntime/openclaw/openclaw.mjs
Contents/Resources/NodeRuntime/openclaw/dist/
Contents/Resources/NodeRuntime/openclaw/node_modules/
Contents/Resources/NodeRuntime/config/openclaw.template.json
```

并执行：

```bash
APP_NODE="$APP/Contents/Resources/NodeRuntime/node/bin/node"
"$APP_NODE" --version
file "$APP_NODE"
```

### 通过标准

- `node` 文件存在并可执行；
- 版本为 `v22.16.0`；
- `openclaw.mjs`、`dist`、`node_modules` 和配置模板存在。

### 测试内容与作用

确认 App 使用 bundle 内的私有 Node，而不是系统 Node；确认 OpenClaw 运行时实际进入最终 `.app`。

---

## 第 3 步：我检查进程和监听端口

### 我执行

```bash
ps -axo pid,ppid,comm,args | grep -iE 'MutualInfection|openclaw' | grep -v grep
lsof -nP -iTCP:18800 -sTCP:LISTEN
lsof -nP -iTCP:18810 -sTCP:LISTEN
```

### 通过标准

应能看到类似进程链：

```text
MutualInfectionMac.app
└── NodeRuntime/node/bin/node
    └── openclaw.mjs gateway run
```

并且：

- 主 gateway 监听 `127.0.0.1:18800`；
- a2a HTTP 监听 `127.0.0.1:18810`；
- 不是由用户系统 Node 启动。

### 测试内容与作用

确认 App 已自动启动 OpenClaw，并验证两个服务是否成功监听预期端口。

---

## 第 4 步：我检查运行日志

### 我执行

根据当前构建类型定位日志。Release 沙盒通常位于：

```bash
CONT="$HOME/Library/Containers/com.HarmonyOSInterconnection.app/Data"
LOG="$CONT/Library/Logs/MutualInfectionMac/NodeRuntime"

tail -100 "$LOG/runtime.log"
tail -100 "$LOG/stderr.log"
```

### 通过标准

`runtime.log` 应出现：

```text
a2a-gateway: HTTP listening ... 127.0.0.1:18810
```

`stderr.log` 不应出现：

```text
Cannot set property signal
```

### 测试内容与作用

验证 Swift 是否收到 OpenClaw ready 信号，并确认 Node 22 已解决此前 Node 26 的 `IncomingMessage.signal` 错误。

---

## 第 5 步：我检查两个服务接口

### 5.1 主 gateway

```bash
curl -i --max-time 5 http://127.0.0.1:18800/health
```

#### 通过标准

HTTP 状态为 `200`，响应包含：

```json
{"ok":true,"status":"live"}
```

#### 测试内容与作用

确认主 OpenClaw gateway 不只是进程存在，而是已经可以正常提供服务。

### 5.2 a2a agent-card

```bash
curl -i --max-time 5 \
  http://127.0.0.1:18810/.well-known/agent-card.json
```

#### 通过标准

HTTP 状态为 `200`，响应 JSON 至少包含：

```text
protocolVersion: 0.3.0
name: MutualInfectionMac
skill: chat
```

#### 测试内容与作用

确认 a2a gateway 已接入 App，并且外部 A2A 节点能够发现当前节点。

如果返回 `404`，结果记为：

> a2a 端口已监听，但 agent-card 路由失败，A2A 集成不完整。

---

## 第 6 步：我检查配置和沙盒数据

### 我执行

```bash
CFG="$CONT/Library/Application Support/MutualInfectionMac/NodeRuntime/config/openclaw.json"
VER="$CONT/Library/Application Support/MutualInfectionMac/NodeRuntime/config/.template_version"

jq empty "$CFG"
cat "$VER"
jq '.gateway.port' "$CFG"
jq '.plugins.entries."a2a-gateway".config.server.port' "$CFG"
grep -n 'configVersion' "$CFG" || true
```

同时检查：

```bash
find "$CONT/Library/Application Support/MutualInfectionMac/NodeRuntime" -maxdepth 3 -type f -print
find "$HOME/.openclaw" -maxdepth 2 -type f -print 2>/dev/null
```

### 通过标准

- `openclaw.json` 是合法 JSON；
- `.template_version` 为 `2`；
- gateway 端口为 `18800`；
- a2a 端口为 `18810`；
- `openclaw.json` 不包含顶层 `configVersion`；
- 运行配置和状态写入 App 容器目录；
- 不因本次 App 启动污染 `~/.openclaw`。

### 测试内容与作用

验证 Swift 注入的 `OPENCLAW_HOME`、`OPENCLAW_STATE_DIR`、`OPENCLAW_CONFIG_PATH` 生效，并验证 sandbox 下的配置隔离。

---

## 第 7 步：你退出 App，我检查进程清理

只有在我完成前六步检查并明确告诉你“可以退出”后，执行本步骤。

### 你执行

在 Xcode 中点击 Stop，或正常退出 App。等待 3 秒后回复：

```text
App 已退出，请检查清理
```

不要手动执行 `pkill`。

### 我执行

```bash
pgrep -fl 'openclaw.mjs gateway|openclaw-gateway|NodeRuntime/node/bin/node' || true
lsof -nP -iTCP:18800 -sTCP:LISTEN || true
lsof -nP -iTCP:18810 -sTCP:LISTEN || true
```

### 通过标准

- Node/OpenClaw 子进程全部退出；
- `18800` 和 `18810` 端口释放；
- 不需要手动杀进程。

### 测试内容与作用

验证 `applicationWillTerminate → NodeRuntimeManager.stop()` 是否有效，避免 App 退出后留下孤儿进程或占用端口。

---

## 最终判定

我会根据实际检查结果给出以下三种结论之一：

### 通过，可进入业务联调

满足：

- App 内 Node 为 `v22.16.0`；
- App 自动启动 OpenClaw；
- `18800/health` 返回 200；
- `18810/agent-card` 返回合法 JSON；
- 日志 ready 正常；
- 无 Node 26 TypeError；
- 配置和数据隔离正确；
- App 退出后进程和端口均清理。

### 部分通过，需要继续排查

runtime 能启动，但 agent-card、配置隔离、ready 日志或退出清理存在问题。

### 不通过

Xcode 构建失败、App 无法启动 OpenClaw、私有 Node 缺失/版本错误，或两个本地服务无法启动。
