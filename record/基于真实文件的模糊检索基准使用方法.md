# Myers 模糊检索基准

此目录包含 Myers bit-parallel 模糊检索实现、正确性测试和 10,000 条文件名夹具。`MyersFuzzyBenchmark.swift` 用相同候选集与查询，对比 `FuzzyCandidateIndex` 基线实现和 `MyersBitParallelFuzzySearch`。
后半还提供可以直接用于测试的文件名json目录和将其实际创建的指导文件，默认存在plan和myPhoto两个待查询词和精准文件名，以及10个相关文件名可通过当前的标准模糊搜索匹配

## 前置条件

- macOS，且可运行 `swiftc`。
- 从仓库根目录执行以下命令。
- 夹具为 `qol/fuzzy-search-fixture-10000.json`。它应有 10,000 个 `files` 条目和带 `expectedIds` 的查询。

`-module-cache-path` 指向可写的临时目录，避免受限环境使用默认 Swift 模块缓存时失败。

## 运行测试

先验证实现没有改变匹配语义：

```bash
swiftc -module-cache-path /private/tmp/qol-swift-cache -parse-as-library \
  qol/MyersBitParallelFuzzySearch.swift \
  qol/MyersBitParallelFuzzySearchTests.swift \
  -o /private/tmp/myers-tests

/private/tmp/myers-tests qol/fuzzy-search-fixture-10000.json
```

预期输出：`MyersBitParallelFuzzySearchTests passed`。

修改基线实现时，也运行其单元测试：

```bash
swiftc -module-cache-path /private/tmp/qol-swift-cache -parse-as-library \
  qol/FuzzyCandidateMatcher.swift \
  qol/FuzzyCandidateMatcherTests.swift \
  -o /private/tmp/fuzzy-baseline-tests

/private/tmp/fuzzy-baseline-tests
```

## 运行基准

编译并以每个查询 50 次迭代运行：

```bash
swiftc -module-cache-path /private/tmp/qol-swift-cache -parse-as-library \
  qol/FuzzyCandidateMatcher.swift \
  qol/MyersBitParallelFuzzySearch.swift \
  qol/MyersFuzzyBenchmark.swift \
  -o /private/tmp/myers-benchmark

/private/tmp/myers-benchmark qol/fuzzy-search-fixture-10000.json 50
```

第二个参数是每个查询的迭代次数。短测可用 `20`，对比改动时建议使用 `200` 或更高：

```bash
/private/tmp/myers-benchmark qol/fuzzy-search-fixture-10000.json 200
```

每次执行都会重新构造索引；计时部分只包含重复调用 `search` 的时间，不包括 JSON 解码和索引构建。

典型输出：

```text
query=plan baselineAccuracy=precision=1.000 recall=1.000 optimizedAccuracy=precision=1.000 recall=1.000
  baseline=12.345ms total (4050.2 qps)
  myers=4.321ms total (11571.5 qps), speedup=2.86x
```

- `precision`：返回结果中正确结果的比例。
- `recall`：期望结果中被返回的比例。
- `qps`：每秒可执行的查询次数，越高越好。
- `speedup`：`baseline 总耗时 / Myers 总耗时`；大于 `1.00x` 表示 Myers 更快。

性能结果会受机器负载、Swift 版本和迭代次数影响。只比较同一机器、同一夹具、相同迭代次数下的多轮结果。

## 迭代方法

1. 先确定要改变的规则或热点。匹配优先级、Unicode 处理和窗口筛选主要在 `MyersBitParallelFuzzySearch.swift`；基线在 `FuzzyCandidateMatcher.swift`。
2. 对规则变更，在 `MyersBitParallelFuzzySearchTests.swift` 中加入最小回归用例。若改变了夹具查询或期望结果，更新 `GenerateFuzzySearchFixture.py` 后重新生成 `fuzzy-search-fixture-10000.json`，并审查 JSON 变更。
3. 运行 Myers 正确性测试。任何失败都先修正语义，不记录性能结果。
4. 用相同命令连续运行基准至少三次，记录每个查询的 `precision`、`recall`、`qps` 与 `speedup`。仅当两种准确率均为 `1.000` 时，才比较性能。
5. 若结果波动明显，提高迭代次数后重测；不要依据单次最快值作结论。保留修改前后的原始输出，按每个查询比较，而不是只看总体印象。
6. 确认改动后，再运行基线测试和整个 Myers 测试；性能退化或召回变化应作为回归处理。

## 更新夹具

该夹具由固定随机种子生成，执行以下命令可得到可审查、可复现的 10,000 条数据：

```bash
python3 qol/GenerateFuzzySearchFixture.py
```

## 桌面 docs 清单与测试文件生成

`desktop-docs-file-list.json` 是从桌面 `docs` 目录导出的文件清单，目前包含 10,000 个文件。它采用与其他 fixture 相同的顶层结构：

- `version`：清单格式版本。
- `queries`：预留的查询及期望 ID；桌面 docs 清单当前为空数组。
- `files`：文件条目数组。每项包含 `relativePath`、`fileName`、`fileExtension`、`size`、`modifiedAt` 和稳定的 `id`。

清单中的 `relativePath` 是相对于清单源目录的路径，例如 `fixture/documents/example.txt`。生成测试文件时，它会被拼接到目标目录，因此目标 `/private/tmp/docs-fixture` 会产生 `/private/tmp/docs-fixture/fixture/documents/example.txt`。`size` 和 `modifiedAt` 是原始目录的记录信息；`GenerateFilesFromList.py` 不使用它们来决定内容长度。

### 生成一套测试目录

`GenerateFilesFromList.py` 接收清单、目标目录和每个文件的内容长度（单位为字节）：

```bash
python3 qol/GenerateFilesFromList.py \
  qol/desktop-docs-file-list.json \
  /private/tmp/docs-fixture \
  --content-length 512
```

脚本会递归创建清单中所有父目录，并为每个文件写入恰好 512 字节的随机可打印 ASCII 内容。随机内容来自操作系统随机源，因此每次执行内容不同，但文件名和目录结构相同。内容长度可以设为 `0`，用于只测试目录枚举和文件名检索。

默认情况下，只要目标目录中有一个待生成文件已经存在，脚本就会停止并拒绝覆盖：

```bash
python3 qol/GenerateFilesFromList.py \
  qol/desktop-docs-file-list.json \
  /private/tmp/docs-fixture \
  --content-length 1024 \
  --overwrite
```

`--overwrite` 会覆盖清单中的已有文件，但不会删除目标目录中不在清单内的其他文件。脚本会拒绝 `../` 等越出目标目录的 `relativePath`，也会拒绝清单中的重复路径。

### 用于 Myers 实测

生成目录后，可直接把它作为目录检索的输入；文件内容通常不会影响文件名模糊匹配：

```bash
python3 qol/GenerateFilesFromList.py \
  qol/desktop-docs-file-list.json /private/tmp/docs-fixture \
  --content-length 298

swiftc -D FUZZY_SEARCH_CLI -parse-as-library \
  qol/MyersBitParallelFuzzySearch.swift \
  -o /private/tmp/myers-search

/private/tmp/myers-search search plan --root /private/tmp/docs-fixture
```

需要重复测试时，使用新的目标目录可保留前一次结果；使用 `--overwrite` 可在同一目录重建内容。若测试关注索引扫描、文件大小或 I/O，而不是随机内容本身，建议固定 `--content-length`，并在报告中记录目标目录、清单文件和内容长度。
