# Node 运行时第 3 步记录

## 目标

确定 Node 宿主项目的构建产物与依赖策略，保证后续 Xcode 打包时路径固定、产物最小、责任边界清晰。

## 结论

第 3 步采用以下策略：

1. 开发期使用 TypeScript，交付期只使用编译后的 JavaScript 产物。
2. 运行期尽量不携带 `node_modules`，至少在当前最小宿主项目中不需要。
3. 构建依赖仅用于构建阶段，不进入最终运行时分发物。
4. 后续 Xcode 打包阶段优先复制 `dist/`，再按需补充少量静态元数据文件。
5. 如果未来宿主项目引入运行时 npm 依赖，再单独评估是否需要分发裁剪后的 `node_modules` 或改用单文件打包方案。

## 依据

当前 `NodeRuntimeHost/src/index.ts` 只使用了 `node:process` 等 Node 内建模块，没有引入任何第三方包，因此：

- 运行时没有必须携带的 npm 依赖
- 只要有 Node 二进制和编译后的 `dist/index.js`，即可启动
- `node_modules` 目前只会增加体积，不会带来运行时收益

## 推荐构建产物

当前最小宿主项目的推荐交付产物为：

```text
NodeRuntimeHost/
├─ dist/
│  └─ index.js
└─ package.json
```

说明：

- `dist/index.js` 是运行入口
- `package.json` 主要保留项目版本、入口和脚本定义
- `node_modules` 仅保留在开发 / 构建环境，不进入当前运行时包

## 推荐构建流程

建议构建流程如下：

1. 在 `NodeRuntimeHost/` 下执行依赖安装。
2. 执行 `npm run build`。
3. 由后续 Xcode 构建阶段或打包脚本复制 `dist/` 到 app bundle。
4. 运行时直接用 bundle 内 Node 执行 `dist/index.js`。

当前阶段不建议把构建动作放到运行时启动过程中。

## 未来扩展原则

如果后续业务阶段引入第三方 npm 依赖，优先按以下顺序评估：

1. 是否能继续通过编译期静态打包，减少运行时依赖。
2. 是否只需要复制裁剪后的生产依赖目录。
3. 是否需要把 Node 运行时产物单独打包成更稳定的内部分发目录。

只有在确有运行时依赖的情况下，才考虑分发 `node_modules`。
